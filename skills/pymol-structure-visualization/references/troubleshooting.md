# 常见问题与排错

本文按"症状 → 原因 → 解决方案"组织，覆盖 `pymol-structure-visualization`
技能在实际使用中最容易遇到的问题。

---

## 一、输入与解析

### 症状 1.1：报错"输入文件不存在"

```
SkillError: 输入文件不存在: complex.pdb
```

**原因**：路径拼写错误，或当前工作目录不是你以为的那个。

**解决**：

```bash
# 确认文件真的在
ls -la complex.pdb

# 用绝对路径最保险
python .../analyze_contacts.py --input /abs/path/complex.pdb --output ./out
```

Windows 上注意 Git Bash 里 `/c/Users/...` 与 `C:\Users\...` 两种写法，
Python 接受后者。

---

### 症状 1.2：报错"结构里没有链 Z"

```
SkillError: 结构里没有链 ['Z']（可用: ['A', 'B', 'L']）
```

**原因**：链标识不是想当然的 `A`/`B`。

**解决**：错误信息里已经列出了可用链，直接照抄。常见意外来源：

- 对接结果里链被重命名为 `A`、`B`、`C`（受体/配体/水）
- PDB 的 `TER` 记录之后的链
- mmCIF 转换后链号变成整数或带前缀

**注意**：老仓库的 `reset pdb chain model.py` 就是在做链号重写这类操作，
新技能不提供链号重写功能 —— 请在分析前自行处理。

---

### 症状 1.3：原子数比预期少很多

**原因**：多 MODEL 文件只读了**第一个 MODEL**。

```
2026-10-26 21:07:58 | INFO | 结构概要: 3 链 / 13 残基 / 112 原子
```

日志里的"原子"数是实际读入的。如果你的文件是 NMR ensemble（几十个 MODEL）
或轨迹快照，原子数会远小于 `MODEL 数 × 单模型原子数`。

**解决**：确认你要分析的是哪一个 MODEL。本技能固定取第一个 ——
如果需要取其他 MODEL，先把它单独抽出来：

```bash
# 用 pdb_selaltloc 之类的工具，或简单用 awk 抽取第一个 MODEL
awk '/^ENDMDL/{exit} {print}' multi.pdb > model1.pdb
```

---

### 症状 1.4：CIF 文件读不了

**原因**：本技能只解析 PDB 格式。

**解决**：先转换。

```bash
# 用 PyMOL（无需 GUI，-cq 参数）
pymol -cq script.pml
```

或在 Python 里用 `gemmi` / `biotite` 转换。

---

## 二、结果异常

### 症状 2.1：接触数是 0

**排查顺序**：

1. **链选错了** —— 先不加 `--chains` 跑一次全链两两，看有没有任何接触
2. **`--max-distance` 太小** —— 试试 `--max-distance 6.0`（默认）
3. **链确实没有接触** —— 两个无关的蛋白放在一起，本来就没有接触
4. **文件是空的或解析失败** —— 看日志里的"原子"数是不是 0

---

### 症状 2.2：接触数多得不合理（几百上千个）

**原因**：大概率是 `--max-distance` 设得过大。

**判断标准**：一个典型蛋白-蛋白界面的氢键数在 **5-30** 量级。
如果一个界面报出 500 个"氢键"，那一定不是氢键。

**解决**：收紧到 4.0-4.5 Å 再看。

```bash
python .../analyze_contacts.py --input c.pdb --output out/ --max-distance 4.0
```

**另一个原因**：`--include-ambiguous-donors` 打开了。这会让 ASP/GLU
也变成供体，虚增氢键数。确认这是你有意为之。

---

### 症状 2.3：距离出现大量 < 2.0 Å 的接触

**原因**：结构本身有立体冲突（steric clash），或者坐标精度有问题。

**诊断**：

```bash
# 找出最近的几个接触
python .../analyze_contacts.py --input c.pdb --output out/ --json out/c.json
python -c "
import json
d = json.load(open('out/c.json', encoding='utf-8'))
for r in sorted(d['contacts'], key=lambda x: x['min_distance'])[:10]:
    print(f\"{r['label_a']:12s} {r['label_b']:12s} {r['min_distance']:.3f}\")
"
```

**解决**：

- 用 `protein-structure` 技能检查结构质量
- 考虑用 `protein-docking-hdock` 重新对接，拿到无冲突的构象
- 如果只是个别原子异常，可以先接受，但要在报告里说明

---

### 症状 2.4：氢键数明显偏少

**排查**：

1. **受体表不全的旧版本** —— 已修。如果你用的是老仓库脚本，请迁移到本技能
2. **结构没有氢原子** —— 本技能按残基化学性质判定，**不需要氢坐标**，
   所以这一项通常不是原因。但如果你改用了 PLIP 路线，没氢会导致 PLIP
   漏掉大量接触
3. **`--include-ambiguous-donors` 没开** —— 默认情况下 ASP/GLU 不作供体。
   如果你的体系偏酸性（如溶酶体蛋白），可以打开试试

---

### 症状 2.5：盐桥数与预期不符

**原因**：HIS 默认不算正电残基。

老仓库把 HIS 算进正电列表会**虚增盐桥数**（HIS 在 pH 7.4 下只有约 4%
质子化）。如果你需要一个含 HIS 盐桥的体系：

```bash
python .../analyze_contacts.py --input c.pdb --output out/ --include-histidine
```

---

### 症状 2.6：配体接触没有被识别

**症状**：`by_type` 里没有 `Ligand_contact`，或者配体残基根本不在结果里。

**排查**：

1. **配体是 HETATM 且被 `--exclude-hetero` 排除了** —— 检查命令行
2. **配体不在分析的两条链里** —— `--chains` 只接受恰好 2 个链；
   配体在第三条链时，需要把它也纳入分析范围
3. **配体距离蛋白太远** —— 超出 `--max-distance`

**设计说明**：配体接触**不会**被报成 π-π 或疏水接触。
我们不知道配体的芳香环在哪、是否带电，硬套氨基酸分类表会得出无意义结论。
需要精确类型请用 `protein-interactions`（PLIP）。

---

### 症状 2.7：热点残基排序每次跑都不一样

**原因**：排序键里包含了距离，同距离时靠残基编号兜底。如果结构相同，
结果应该是稳定的。

**检查**：确认是不是把 `--max-distance` 改了。改变截断半径会改变接触集合，
热点排序自然会变。

---

## 三、输出问题

### 症状 3.1：Excel 打开 CSV 中文乱码

**原因**：CSV 用 UTF-8 编码，但 Excel 在中文 Windows 上默认按 GBK 解读。

**现状**：本技能的 CSV 用 **UTF-8 with BOM**（`utf-8-sig`）写出，
Excel 双击即可正确识别。如果仍乱码：

- 用 Excel 的"数据 → 从文本/CSV"导入，手动选 UTF-8
- 或用 `iconv -f utf-8 -t gbk contacts.csv > contacts_gbk.csv`

---

### 症状 3.2：产物没有出现在预期目录

**检查**：

1. `--output` 不指定时，默认写到**输入文件同级**的 `<输入名>_contacts/`
2. 日志里会打印每个产物的完整路径 —— 直接看日志最准
3. Windows 上注意盘符锚定：`Path("out") / "C:\\x.json"` 会写到盘符根目录。
   本技能的产物已全部保证在输出目录内，但如果你自己改代码拼接路径要注意这点

---

### 症状 3.3：Mermaid 图渲染失败

**原因**：节点 ID 里含非法字符。

**现状**：本技能已把残基标签里的 `:` 替换成 `_`（`A:ARG10` → `A_ARG10`）。
如果你自己写了 Mermaid 内容，检查节点 ID 是否含 `-`、空格、中文标点。

---

### 症状 3.4：生成的 PyMOL 脚本报错

**检查**：

1. 脚本里的 `cmd.load('complex.pdb', 'complex')` 是**注释掉的** ——
   需要你自己填上实际路径并取消注释
2. 跑法：`pymol -r script.pml`（无 GUI）或在已打开的 PyMOL 里 `run script.pml`
3. 如果提示 `cmd.select` 找不到残基，检查链标识与 CSV 里的 `ChainA`/`ChainB` 是否一致

---

## 四、性能问题

### 症状 4.1：大型复合物运行慢

**原因**：网格划分已经消除了 O(N²)，剩余耗时主要在候选对的距离计算。

**优化建议**：

1. **收紧 `--max-distance`** —— 候选对数量随半径的立方增长
2. **只分析关心的链对** —— `--chains A B` 而不是全部链两两
3. **排除水与离子** —— `--exclude-hetero` 对含大量结晶水的晶体结构很有效

参考量级：5000 原子、6 Å 阈值，通常在 1-3 秒内完成。

---

### 症状 4.2：内存占用高

**原因**：JSON 结果里包含每个接触的完整原子对明细。

对于一个 200 个接触的界面，JSON 约几百 KB，不成问题。
但如果结构很大且 `--max-distance` 放得很宽，可能到几 MB。

**解决**：不需要原子级明细时，只看 `contacts.csv`（只有汇总信息）。

## 五、常见误用

### 误用 1：把本技能的氢键数当作发表级结论

**纠正**：本技能按**残基化学性质**判定氢键，不检查氢原子位置与
D-H···A 角度。这是**缺少氢坐标时的最佳近似**，不是精确判据。

发表级别的相互作用分析请用 `protein-interactions`（PLIP）。

### 误用 2：把 `--max-distance` 当作类型阈值

**纠正**：`--max-distance` 是**几何检测**的截断半径。
氢键、盐桥各自的判据阈值（3.5 / 4.0 Å）是固定的，不随它改变。

把 `--max-distance` 设成 3.0 并不会"让氢键判据变成 3.0"，
而是让 3.0-3.5 Å 的氢键**根本不被检测到**。

### 误用 3：期望结果与老仓库一致

**纠正**：老仓库的分类表互相矛盾，且接触判定方式（残基级笛卡尔积）
本身是错的。老仓库报出的接触数通常**偏多**，且类型分布不合理。

两者的差异是**预期的** —— 本技能修的就是这些问题。

### 误用 4：在脚本里 import pymol

**纠正**：核心分析零第三方依赖。PyMOL 只应该出现在**生成物**里。
如果你要在自己的脚本里做可视化，生成 `.pml` 文件然后执行它，
不要把 PyMOL 变成 import 依赖。

## 六、如何提问

遇到未收录的问题时，请在 Issue 中提供：

- 完整的命令行与 `--verbose` 日志
- 输入 PDB 的**基本信息**（链数、残基数、原子数 —— 从日志里抄）
- 期望结果与实际结果的差异
- Python 版本
- 如果涉及数值分歧，附上 `contacts.csv` 的前几行

**不要**附上大型结构的完整 PDB 文件 —— 提供足以复现的最小片段即可。
