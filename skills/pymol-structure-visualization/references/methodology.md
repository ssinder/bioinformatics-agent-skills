# 方法学：链间残基接触的判据与算法

本文说明 `pymol-structure-visualization` 技能里每一个判据的来源、每一个
算法选择的理由，以及从老仓库 `pymol_show/` 移植时修掉的 6 个缺陷。

---

## 1. 为什么接触类型不能靠距离猜

一个直觉的做法是："距离 < 3.5 Å 就算氢键"。这个做法是错的，原因有三：

**第一，距离不携带化学信息。** 两个丙氨酸残基的碳原子相距 3.4 Å，
它们之间**不存在**氢键 —— 碳上既没有孤对电子，也没有可离散的氢。
反过来，一对 ARG 的胍基氮与 ASP 的羧基氧相距 2.9 Å，
它们的相互作用类型完全由**残基的化学身份**决定，与距离无关。

**第二，同一对残基可以同时满足多种类型。** ARG 的胍基与 ASP 的羧基之间
既有质子化的 N–H···O 氢键，又有静电盐桥。只报一个类型会丢失信息；
只报"距离最短的那个"则会随机地在氢键与盐桥之间摇摆。

**第三，不同类型的"有效距离"不同。** 疏水接触可以在 4.5 Å 仍有意义，
但把 4.5 Å 的两个羰基氧叫"氢键"显然是错的。

因此本技能的判定链条是**三级**：

```
原子层面 → 残基层面 → 距离层面
（谁的原子）  （什么化学组合）  （够不够近）
```

实现上按残基层面判定，因为 PDB 文件通常**没有氢原子坐标**，
无法用原子级的供受体 + H 角度判据（那是 PLIP 的做法）。
残基层面是**在缺少氢坐标时的最佳近似**。

## 2. 距离阈值的来源

| 类型 | 阈值 | 依据 |
|------|------|------|
| 氢键 | 3.5 Å | N···O 氢键的距离通常 2.6-3.2 Å；3.5 Å 是"还能算氢键"的上限 |
| 盐桥 | 4.0 Å | 盐桥比氢键稍长，因为静电作用距离衰减更平缓 |
| 疏水接触 | 4.5 Å | 范德华接触的实际范围 |
| π-π 堆积 | 5.0 Å | 芳香环中心距通常 3.4-4.0 Å，5.0 Å 覆盖偏斜堆积 |
| 阳离子-π | 6.0 Å | 阳离子-π 的有效距离最长 |

**这些阈值全部继承自老仓库的 `interaction count.py`** —— 它们本身是合理的，
问题不在阈值，而在老实现没有正确地把"化学条件"和"距离条件"组合起来。

**阈值可以调吗？** `--max-distance` 只控制**几何检测**的截断半径，
不改变每个类型的判据阈值。如果把 `--max-distance` 设成 3.0，
那么距离 3.2 Å 的氢键仍然会被**分类**为氢键（因为 3.2 < 3.5），
只是它根本不会被检测到 —— 因为几何检测先按 `--max-distance` 筛掉了。

所以正确用法是：**`--max-distance` 不小于 6.0**（默认），让它只起
"粗筛"作用；用 `--min-distance` 来做精细的下限过滤。

## 3. 化学分类表的取舍

### 3.1 供体表：为什么 ASP/GLU 不在里面

老仓库有两个脚本，各写了一套供体表，而且**互相矛盾**：

```python
# interaction count.py
donors = ["LYS", "ARG", "HIS", "SER", "THR", "TYR", "ASN", "GLN"]

# hbond count.py
donor_residues = ["LYS", "ARG", "HIS", "ASP", "GLU", "SER", "THR", "TYR"]
```

后者把 ASP/GLU 也列为供体。这在化学上是错的：

- 羧基（–COOH）的 pKa ≈ 4.1
- 生理 pH（7.4）下，羧基**几乎完全去质子化**（比例 > 99.9%）
- 去质子化的羧酸根上**没有可离散的氢**，因此不构成氢键供体

把它们当供体会**系统性地虚增氢键数量** —— 而且是最容易虚增的那一类，
因为 ASP/GLU 在蛋白表面极其常见。

现在 ASP/GLU 位于 `DONORS` 之外，需要时可用 `--include-ambiguous-donors`
显式开启（对应"在 pH < 4 的环境里"这种特殊情况）。

### 3.2 受体表：老版本漏了 SER/THR/HIS/TRP

```python
# interaction count.py
acceptors = ["ASP", "GLU", "ASN", "GLN", "TYR"]

# hbond count.py
acceptor_residues = ["ASP", "GLU", "TYR"]
```

两套表都漏掉了 SER（羟基氧）、THR（羟基氧）、HIS（咪唑氮）、
TRP（吲哚氮）。这些残基在蛋白表面非常常见，漏掉会让氢键数**偏少**。

本技能统一为：

```
ACCEPTORS = {ASN, GLN, HIS, SER, THR, TYR, ASP, GLU}
```

注意 HIS **既**是供体**又**是受体 —— 咪唑基的 N 可以质子化（供体）
也可以去质子化（受体），这正是它需要单独讨论的原因。

### 3.3 正电残基：为什么 HIS 要单列

```python
# 老版本
positive = ["LYS", "ARG", "HIS"]
```

HIS 的咪唑基 pKa ≈ 6.0。在生理 pH（7.4）下：

$$\text{质子化比例} = \frac{1}{1 + 10^{(7.4 - 6.0)}} = \frac{1}{1 + 25.1} \approx 3.8\%$$

也就是说只有约 **4%** 的 HIS 处于质子化状态。把全部 HIS 都算作正电残基，
会**虚增约 25 倍**的 HIS 参与的盐桥。

本技能的处理：

```python
POSITIVE = frozenset({"LYS", "ARG"})        # 生理 pH 下几乎完全质子化
POSITIVE_PARTIAL = frozenset({"HIS"})      # 约 4% 质子化
```

默认只算 `POSITIVE`；`--include-histidine` 打开后 HIS 也参与盐桥与
阳离子-π 判定。

### 3.4 疏水表：老版本漏了 CYS

```python
# 老版本
hydrophobic = ["ALA", "VAL", "LEU", "ILE", "MET", "PHE", "TRP", "PRO"]
```

CYS 缺失了。CYS 的硫醇基确实有一定极性，但在蛋白核心与结合界面的
疏水核心中，CYS 扮演的是疏水角色。本技能把它补进 `HYDROPHOBIC`。

### 3.5 芳香族表

```python
AROMATIC = frozenset({"PHE", "TRP", "TYR", "HIS"})
```

老版本是 `["PHE", "TYR", "TRP"]`，漏了 HIS。咪唑环虽然只有 5 元环，
但确实具备 π 电子体系，可以参与 π-π 与阳离子-π 相互作用。

### 3.6 配体：为什么单独标记而不是硬套分类表

配体（LIG、HEM、ADP……）不是标准氨基酸，我们**不知道**：

- 它的芳香环在哪里
- 它是否带电
- 它是极性还是非极性

如果把配体硬塞进氨基酸的分类表，会得到无意义的结论 ——
比如把苯环配体当成"疏水残基"（它确实疏水，但结论是废话），
或者把带电配体当成"负电残基"（电荷数、质子化态全都不知道）。

但配体接触**也不该被静默丢弃** —— 配体结合位点往往就是研究热点本身。

所以本技能的做法是：

```python
LIGAND_CONTACT = "Ligand_contact"
```

任一侧是非标准残基时，接触被标记为 `Ligand_contact`，距离照常报告，
但不套用残基级分类。**需要精确类型时用 `protein-interactions`（PLIP）**，
它有完整的配体化学模板。

水分子单独识别（`residue_kind` 返回 `"water"`），水-水接触不报告。

## 4. 网格空间划分

### 4.1 为什么不用暴力两两比较

一个典型复合物有 5000-20000 个原子。暴力两两比较是：

$$\frac{20000 \times 19999}{2} \approx 2 \times 10^8 \text{ 次距离计算}$$

纯 Python 单次距离计算约 1-2 µs，即 **200-400 秒**。这在批处理场景下
完全不可接受。

### 4.2 算法

1. 把原子按 `cell_size = max_distance × 1.0001` 装进立方桶
   - 桶索引 `floor(x / cell_size)`
2. 遍历每个桶的 **3×3×3 邻域**（共 27 个桶）
3. 对候选原子对算真实欧氏距离，保留在阈值内的
4. 把原子级接触归并到残基对级，记录最小距离

复杂度从 O(N²) 降到接近 O(N) —— 实际取决于空间密度，但典型蛋白上
通常快 50-200 倍。

### 4.3 桶边长为什么要乘 1.0001

桶是**左闭右开**区间 `[k·s, (k+1)·s)`。若 `s == max_distance`，
两个距离恰好等于 `max_distance` 的原子可能被分到桶索引相差 **2** 的桶里
（一个在桶 k 的右端，一个在桶 k+2 的左端），此时扫 3×3×3 邻域会漏检。

早期实现扫 5×5×5（半径 2）来保险。改成 `s = max_distance × 1.0001` 后：

- `s` 严格大于最大距离 ⇒ 桶索引差最多为 1 ⇒ 扫 3×3×3 即已覆盖
- 浮点余量 0.01% 足以吸收边界抖动

候选对数量因此减少约 **4.6 倍**（125 → 27），而结果完全一致 ——
这一点由 `tests/test_pymol_structure_visualization.py::test_grid_matches_brute_force`
逐对比对验证。

### 4.4 一致性保证

网格划分是**纯优化**，不能改变结果。测试里用 60 个确定性伪随机原子，
把网格结果与暴力两两比较的结果**逐个残基对**对比（距离保留 6 位小数），
必须完全相等。

## 5. 多类型叠加而非互斥

```python
def classify_pair_multi(res_a, res_b, distance, ...) -> list[str]:
```

返回**全部**匹配的类型，按优先级排序：

```
氢键 > 盐桥 > π-π 堆积 > 阳离子-π > 疏水接触
```

优先级反映的是"特异性"：氢键比疏水接触更具体，盐桥比一般的极性接触更具体。

`classify_pair()` 只返回第一个匹配的类型，用于需要单一值的场合。

**为什么 π-π 和阳离子-π 要单独处理？** 芳香族残基同时也是疏水残基。
如果按优先级互斥处理，PHE–PHE 会被报成疏水接触，π-π 信息就丢了 ——
但 π-π 堆积是比疏水接触**信息量大得多**的结论。所以这两类无论是否同时
满足疏水条件，都独立报出。

## 6. 从老仓库移植时修掉的 6 个缺陷

### 缺陷 1：报告的是"各自靠近"而不是"互相接触"（最本质）

老实现：

```python
cmd.select("tmp1", f"{sel1} within {cutoff} of {sel2}")   # 选出残基
cmd.select("tmp2", f"{sel2} within {cutoff} of {sel1}")
# ...然后对两个残基集合做笛卡尔积
```

`within` 选择器选出的是**满足条件的残基**，不是原子对。之后对两个残基集合
做笛卡尔积，意味着：只要 A 侧的某个残基内部有原子在截断距离内，
且 B 侧的某个残基内部也有原子在截断距离内，这一对就被记为接触 ——
**哪怕 A 的那个原子和 B 的那个原子相距 10 Å**。

举例：ARG 侧链很长（伸到 6 Å 外），ASP 侧链也很长。ARG 的末端原子
可能靠近了链 B 上另一个完全无关的残基，而 ASP 的末端原子靠近了链 A 上
另一个残基。老实现会把 (ARG, ASP) 记成一对氢键，但它们真正的接触原子
可能相距 15 Å。

**本技能的修法**：全程在**原子级**做距离计算，只有真正在阈值内的
原子对才被记录，然后再归并到残基对。

### 缺陷 2：必须启动 PyMOL GUI

老脚本全部以 `pymol.finish_launching(['pymol'])` 开头，结尾 `cmd.zoom()`。
后果：无 PyMOL 的机器上完全跑不了；CI 里无法测试；每次运行都要弹 GUI。

**本技能的修法**：几何计算全部是纯 Python；PyMOL 只出现在**生成的
`.pml` 文本**里，作为产物。

### 缺陷 3：硬编码个人路径

```python
pdb_path = r"C:\Users\DELL\Desktop\1.pdb"
out_csv = r"C:\Users\DELL\Desktop\AC_interactions.csv"
root_dir = r"C:\Users\DELL\Desktop\output"
```

**本技能的修法**：全部走命令行参数。

### 缺陷 4：分类表互相矛盾

见第 3 节。**本技能的修法**：统一到 `contact_chemistry` 一个模块。

### 缺陷 5：文件名带空格

老脚本名如 `interaction count.py`、`hbond count.py`。在 shell 里必须加引号；
PyMOL 的 `run` 命令对带空格路径的处理也容易出问题。

**本技能的修法**：文件名全部是合法的 Python 模块名
（`contact_chemistry.py` / `contact_geometry.py` / `analyze_contacts.py`）。

### 缺陷 6：PLIP 结果汇总靠固定路径 + pandas 依赖

老 `use plip find interact region.py` 遍历 `C:\Users\DELL\Desktop\output\*`
下的 `interaction_residues.txt`，用 pandas + openpyxl 汇总成 Excel。

**本技能的修法**：PLIP 报告解析交给既有的 `protein-interactions` 技能
（避免重复实现）；本技能的核心分析零第三方依赖。

## 7. 为什么要用 `protein-structure` 的解析器

`analyze_contacts.py` 优先 `import pdb_parser`（来自 `protein-structure`
技能），不可用时退回内置的精简解析。

好处：

- **解析逻辑只有一份**，两个技能对同一个 PDB 的理解必然一致
- `protein-structure` 的解析器处理了插入码、交替位点、多 MODEL、
  非标准残基等边界情况

内置兜底解析器只做列切片与浮点转换，用于解析器不可用时的降级。

## 8. 方法学的局限

诚实地说明这套方法的边界：

1. **残基层面 ≠ 原子层面**。真正的氢键需要氢原子的位置与 D-H···A 角度。
   没有氢坐标时，残基层面是最佳近似，但不是精确判据。
   **发表级别请用 PLIP**（`protein-interactions`）。

2. **距离阈值是通用近似**，不是力场参数。对"这个接触是不是真的存在"
   的边界情况（比如 3.4 Å 的氢键），不同工具的判定会不一致。

3. **不考虑水介导的接触**。两个残基之间隔着 2 个水分子仍可能形成有效
   氢键网络。本技能只看直接接触。

4. **电荷态是按 pH 7.4 假定的**。特殊环境（酸性溶酶体 pH 4.5、
   蛋白内部低 pH 腔）需要重新考虑 ASP/GLU 的质子化状态 ——
   这正是 `--include-ambiguous-donors` 存在的意义。

5. **不做能量计算**。接触数量与强度不等于结合亲和力。

跑完分析后，按顺序核对：

- [ ] `by_type` 各项之和 ≥ 有类型的接触数（因为一个接触可多类型）
